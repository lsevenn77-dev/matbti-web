# 나솔너솔 (나도 솔로, 너도 솔로) — 시제품 v0.1

12명이 한 방에서 하는 진행 흐름을 검증하는 웹/PWA 시제품이다. 최종 그래픽과 실제 음성은 아직 들어 있지 않다.

> 이 폴더는 맛BTI 저장소 안에 임시로 둔 독립 프로젝트다. 루트의 Next.js 앱과 코드나 의존성을 공유하지 않는다.
> 나중에 별도 저장소로 옮기려면 이 폴더를 그대로 옮기면 된다.

## 실행

```bash
cd nasolneosol
npm install
npm run dev          # http://localhost:8080  (10배속 + 개발도구: 봇 채우기, 윈도우에서도 동작)
npm start            # 실제 시간, 개발도구 꺼짐
npm test             # 진행 엔진 단위 테스트
npm run sim          # 실제 WebSocket 클라이언트 12개로 전체 회차 진행 + 트래픽 측정
node scripts/simulate.js 60 twoDates   # 비교안(랜덤 데이트 삭제) 시뮬레이션
```

환경변수는 `PORT`, `TIME_SCALE`, `DEV_TOOLS=1`, `PRESET=threeDates|twoDates`, `VOTER=random|male|female`, `BOT_INTRO_SEC`, `DATA_DIR`이다.
설명은 `server/index.js` 맨 위에 있다.

혼자 테스트하는 방법: 가입 → 입장 대기 → **개발: 봇으로 나머지 채우기**. 봇 11명과 한 회차가 진행된다.

## 구조

| 파일 | 역할 |
|---|---|
| `server/config.js` | 모든 규칙·시간 설정. `[확정]`과 `[임시]`를 구분해 표시한다. 3회 원안과 2회 비교안 프리셋 포함 |
| `server/room.js` | 한 방의 진행 엔진. 서버 시각으로 단계를 진행하고, 투표·데이트 배정·미니게임·지목·최종 매치를 처리한다. 공개 필드와 음성·채팅 권한도 계산한다 |
| `server/voice.js` | 음성 어댑터. 지금은 **모의 구현**이다. 권한이 바뀐 부분만 publish/subscribe 작업으로 만든다 |
| `server/store.js` | 회원·사진·회차 기록 저장소. 지금은 파일로 저장하고, 나중에 Supabase/R2로 교체할 자리다 |
| `server/bots.js` | 개발용 봇 |
| `server/index.js` | HTTP 서버(가입·사진·정적 파일)와 WebSocket 서버(대기열·게임 상태) |
| `client/public/` | 웹 클라이언트(Three.js 3D, UI), PWA 매니페스트·서비스 워커·아이콘 |

## 실제로 동작하는 것 / 모의 구현인 것

동작함 (테스트와 시뮬레이션으로 확인):
- 가입(사진·성별·나이·직업·사는 곳)과 선착순 대기열. 남녀 6명씩 모이면 방이 만들어진다
- 성별 입장 순서대로 가명(태양…노을 / 이슬…여름)과 고정 캐릭터 12종을 배정한다
- 첫인상 투표 성별 랜덤 추첨, 중복 선택에 따른 N:1 그룹(6:1 포함), 0표인 사람은 숙소에서 텍스트 대화
- 자유 구경 5분(바닥을 눌러 이동), 자기소개 순서·발표자 강조·작은 프로필 사진·일찍 끝내기·불참자 건너뛰기
- 자기소개 전에는 나이·직업·사는 곳을 **서버에서 아예 보내지 않는다** (공개 시점은 `afterEach`/`afterAll` 설정)
- 반응 속도 미니게임 → 데이트권(제안 A) 또는 전원 지목 순서(제안 B) → 중복 없는 1:1 지목
- 3차 랜덤 데이트(이전 상대 회피) 켜기/끄기, 최종 상호 선택 매치
- 연락처 교환(기본 꺼짐). 켜면 양쪽 모두 동의했을 때만 공개된다
- 채팅 채널 권한: 데이트 그룹 / 성별 숙소 / 공용 거실. 서버가 검사한다
- 재접속하면 서버의 최신 단계로 복구한다. 중복 요청(투표·지목·최종 선택)은 한 번만 처리한다
- PWA: 매니페스트, 아이콘, 서비스 워커(버전별 캐시, 진행 중 강제 업데이트 안 함), Android 설치 버튼, iPhone 안내

모의 구현 / 미구현:
- **음성: 실제 소리는 송수신되지 않는다.** 권한 계산(발표자 1명 송출, 데이트 그룹끼리만)과 화면 표시만 된다. 실제 연동은 `CloudflareSfuAdapter` 자리에 한다
- 회원 인증은 브라우저에 저장한 토큰뿐이다. 로그인, 본인확인, 연령 확인은 없다
- 사진 검수, 신고, 차단 기능이 없다
- 그래픽: 코드로 만든 단순 도형 캐릭터와 공간이다. 아이콘도 임시다. 최종 자산은 별도로 제작한다
- 미니게임 부정행위 방지는 검증하지 않았다 (클라이언트가 잰 반응 시간을 서버 측정값 이하로만 제한)
- 나이 선호 매칭은 없다 (순수 선착순)
- 진행 도중 빈자리 대체 입장 기능은 없다

## 측정값 (시뮬레이션, 2026-11-23)

- 1인당 게임 상태 수신량은 회차당 약 **350KB**다. 69분 기준으로 평균 **약 90 B/s/인**이다.
  사진, 3D 정적 파일, 음성은 제외한 값이다. 봇의 채팅량과 이동량이 실제보다 적어서 실제 값은 더 클 수 있다.
  상태를 매번 전체 전송하고 있어서, 변경분만 보내면 더 줄일 수 있다.
- 기획서 추정치(1~5KB/s)보다는 훨씬 작다. 그래도 실제 12인 플레이로 다시 재야 한다.

## 결정이 필요한 규칙

전부 `server/config.js`에 설정으로 분리해 두었다. 현재 값은 임시값이다.
1. 랜덤 데이트 유지(3회) 또는 삭제(2회). 현재 값은 3회
2. 자기소개 1인 시간. 현재 값은 2분
3. 2차 보상: 데이트권 3장 또는 전원 지목 순서. 현재 값은 데이트권 3장
4. 프로필 공개 시점. 현재 값은 각자 소개가 끝날 때마다 공개
5. 첫인상 기권과 그룹 상한. 현재 값은 기권 허용, 상한 없음
6. 2차 지목 수락과 거절 절차. 현재 미구현
7. 최종 결과 공개 범위. 현재 값은 본인 결과만
8. 연락처 교환 채택 여부. 현재 꺼짐
